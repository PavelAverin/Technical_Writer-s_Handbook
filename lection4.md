# Требования к документационному инструментарию

## Документационный инструментарий

- Разработка
- Ревью
- Хранение
- Публикация

### Инструментарий хранения

- Однозначная локация документа (файл в репозитории, URL...)
- Автоматически поддерживаемая история ревизий
- Обнаруживаемость (discoverabillity): возможность увидеть весь список документов

*Все это очень сильно облегчает ревью*

### Инструментарий ревью

- Комментарии (желательно, к фрагменту текста, а не ко всему тексту)
- Workflow комментариев: закрытие, переоткрытие, ветки дискуссий...
- Точечное отслеживание изменений: что же поменялось с предыдущей ревизии?

*Без этого комментарии и изменения придется передавать по отдельному каналу коммуникации*

*Инструментарий ревью не создаст сами процессы ревью*

### Подходящие инструменты на данный момент

- Google Docs
- Confluence
- MS Word + Office365 + OneDrive

### Инстурменты публикации

- Конвертация во что-то удобочитаемое
  - PDF
  - HTML
  - Красивый DOCX

### Инструменты разработки

- Переиспользование контента
  - Блоки текста
  - Текстовые переменные
- Строгое соответсвие визуальным шаблонам
  - ГОСТ
  - Корпоративная айдентика
- Скорость создания контента
  - Удобный WYSIWYG
  - Простая разметка

### Help Authoring Tools, HATs

- Author-it
- MadCap Flare
- Help&Manual

Этот инструментарий имеет ряд особенностей:
- В перввую очередь инструментарий разработки
- Процессы ревью, подходы к хранению и пр. вторичны
- В меньшей степени применимы для "быстрых документов"
- Барьер входа в создание высок

### Специфические желания

- Сравнение произвольных ревизий
- Blame: кто автор этой строчки?
- Синхронизация изменений в коде и изменений в документации
- Автоматизированная публикация

Из этого вытекает следующий подход...

### Docs as code

Давайте относиться к документации как к коду!\
Хранить ее в plain text в репозитории!

- Легковесные языки разметки
  - Markdown
  - Asciidoc
  - RST
- Экосистема инструментария конвертации и публикации
  - PDF
  - Многостраничный HTML
  - DOCX
- Большинство инструментов публикации
  - бесплатны
  - открыты
  - встраиваются в CI/CD-конвейеры
- Все преимущества Git
  - diff
  - blame
  - merge

#### Ревью в docs as code

- Давайте переиспользуем инструментарий для кода!
- Pull/merge requests в вашем любимом GitHub/GitLab/Bitbucket

### Docs as code, плюсы

- Невероятная гибкость инструментария
- Синхронизация изменений в коде и в документации
- Автоматизация публикации "из коробки"

### Docs as code, минусы

- Ревью не всегда удобны
- Высокая стоимость первичной настройки
- Все еще высокий барьер создания документации
- Иногда очень не хватает WYSIWYG
